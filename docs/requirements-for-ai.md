# 給 AI 的需求說明：新北市少年培力園的網站

這份文件寫給**協助建網站的 AI** 讀。內容分三部分：

1. **通用需求與偏好**：不管做哪一個網站都適用。開始任何新網站之前先讀這段。
2. **參考規格**：已經上線的「活動報名＋場地借用」網站做了什麼，做類似網站時可以照抄或改。
3. **踩過的坑**：做過、失敗、改掉的事，不要再犯一次。

用詞：**必須**＝一定要做；**避免**＝除非使用者明確要求，否則不要做；**建議**＝預設這樣做。

---

## 第一部分：通用需求與偏好

### 1. 使用者是誰

- 使用者是**新北市少年培力園的社工**，不是工程師。服務對象是 12–18 歲的少年。
- 網站的使用者有三種：**少年**（多半用手機）、**少年的家長／外部借用人**、**園內工作人員**（用電腦也用手機）。
- 工作人員會在現場（上課中、簽到時）用網站，所以畫面要**一眼看得懂、少點幾下**。

### 2. 溝通方式

- **必須**用**繁體中文**回覆，介面文字也全部繁體中文（台灣用語：「資料」「檔案」「網址」「手機」）。
- **必須**用白話解釋，不講技術名詞；需要講的時候附一句「這是什麼、對您有什麼影響」。
- 回報結果時講**做了什麼、使用者現在會看到什麼、要不要他做什麼**。不要只講程式改了哪裡。
- 需要使用者動手的步驟（例如到 Vercel 設定）**必須**一步一步寫，標出按鈕名稱。
- 沒辦法確認的事（例如連不到外部服務、沒有真的用手機測）**必須**老實講，並請使用者實際試一次。
- 使用者常用截圖指出問題（紅筆圈起來）。看到截圖要先找出**他圈的那個地方**真正的問題。
- 使用者一句話的需求常常很短（例如「額滿的應該放在開放報名中」），要推想合理的完整做法，做完再說明細節與取捨；真的有兩種方向、差別很大時才問。

### 3. 技術棧（沿用，不要換）

- **Node 22（ESM）**，後端只依賴 `pg`，不用框架。前端是**原生 JavaScript**，不用 React／打包工具。
- 資料庫：**Neon Postgres**。部署：**Vercel**（serverless，檔案系統唯讀）。
- 程式碼放 GitHub；推上 `main` 就會自動上線。
- 機密設定（密碼、金鑰、token）一律放 **Vercel 環境變數**，改完要 Redeploy 才生效。
- 安全標頭有嚴格的 CSP（`script-src 'self'`），**避免**載入外部 CDN 的程式。

### 4. 隱私與安全（最重要）

- **必須**：前台公開頁面**不顯示少年完整姓名**（例：「王Ｏ明」）。
- **必須**：前台**不顯示剩幾個名額**，只顯示「開放報名／候補中／已額滿」。
- **必須**：密碼、私鑰、API token **不要叫使用者貼在聊天室**，請他直接貼進 Vercel 環境變數。
- **必須**：真實個資（姓名、身分證、電話）**不放進程式碼或 GitHub**。測試一律用假資料，送出程式前檢查有沒有混進去。
- **必須**：讓人「查自己的資料」時要驗證：姓名＋身分證字號；要**修改**資料時再加出生年月日（三項全對）。
- 後台只有一組共用密碼；建議設 `SESSION_SECRET`。
- 身分證字號、電話、生日要自動整理格式（大寫、去空白、全形轉半形、西元／民國都能輸入）。

### 5. 做事的方式

- **必須**做完先自己測（用假資料、手機和電腦兩種寬度），確定沒問題才說「好了」。
- **建議**：改動要「不會把人卡住」。外部服務（縮網址、人機驗證、行事曆）失敗時要**有備案**，不能讓報名或預約送不出去。
- **建議**：新功能**預設開著的選項要保守**；可能造成困擾的功能（人機驗證、通知）先做成可以用環境變數關掉。
- **建議**：統計數字只要有一個來源。同一個數字在兩個頁面出現時，**算法必須一樣**（例如場地使用次數，借用頁和月報要對得起來）。
- **避免**自己編數字：系統沒有可靠來源的欄位就留白給人填，不要猜。
- 刪除類操作要**輸入名字確認**，避免手滑。
- 表單要**自動儲存**或至少暫存（填到一半跑掉不會不見）。

### 6. 介面偏好

- 手機優先，字要夠大（使用者嫌過「字太小」）。
- 頁面**不要太長**：次要內容收起來（點開才看），標題右邊寫重點摘要（例：「3 人填過」）。
- 常用、最重要的放最上面（例如前後測頁最上面就是「誰還沒填」）。
- 選項放在**使用者找它的地方**（例：「每天場地不一樣」要放在「使用空間」旁邊，不是藏在別的收合面板裡）。
- 狀態用顏色區分：可以做的事用綠色、需要注意的用橘色、已結束或不能用的畫淡。
- 下載的 Excel **格式要完全照園方原本的檔案**（字型、框線、欄寬、工作表名稱）。

## 第二部分：參考規格（已上線的活動報名＋場地借用網站）

### A. 少年報名

- 報名欄位照園方原本的 Google 表單：
  - 學生主檔（只填一次）：姓名、身分證、生日、性別、身分別（一般／原住民／新住民）、特殊家庭狀況、學校、年級、居住區域（限新北市 29 區）、地址、電話、手機、LINE ID、Email。
  - 監護人（保險用）：姓名、身分證、生日、國籍、關係、電話。**可以先空著、事後補**（少年在「查詢我的報名」補，要再填生日確認本人；工作人員在後台補；活動名單會列出還沒補齊的人）。
  - 每次報名都要填：從哪裡得知、報名原因（至少 2 項）、全程參與承諾。
- **報名過一次就不用再填**：之後輸入姓名＋身分證＋生日就帶出資料，有變動可以當場改。
- 名額、候補名額、報名截止日、招收年齡（不符仍可報名，只是提示）。
- **選天數報名**：多天活動可以只報其中幾天，每天各自算名額與候補。
- 首頁分頁：**開放報名中**（含額滿的，排在後面）／**已截止**（過截止日或工作人員關閉）／**過往活動**。
- 「查詢我的報名」：看報了什麼、正取或候補第幾位、有沒有錄取。

### B. 活動管理（後台）

- 單日活動或連續性課程（連續每天、每週固定星期、隔週、手動加日期），之後可以再加日期。
- 使用空間可複選；**多天活動每天可以用不同場地**。佔用的場地在那個時段別人借不到；存檔時撞場地要提醒。
- 新增活動自動同步 Google 行事曆（依負責工作人員代號上色）。同步失敗不能擋存檔，但要提醒。
- 活動分類（月報用，前台看不到）：方案分類、服務類型、細分類。統計專用的選項（「專業人員教育訓練」「工作人員增能」）只在月報那邊出現。
- 活動名單：搜尋、工作人員備註、不錄取／遞補、刪除（輸入名字確認）、下載報名資料與保險名冊（CSV，Excel 開不亂碼）、列印。
- 「複製連結」複製短網址；每個活動有 QR Code，可下載成圖片（下面印活動名稱和網址，放海報用）。

### C. 簽到與出席

- 全部活動共用一張簽到 QR：掃了選課程、填姓名與身分證就完成。現場臨時參加的也能簽到。
- 出席總覽（報名者 × 場次的勾勾表）；每個活動的出席人次分佈（地區、年齡、身分別、性別），可切全部／第一～四季。
- 一次簽到算一人次；年齡用**上課那天**算。

### D. 前後測

- 題庫（量表 1–5、單選、複選、開放式問答），每個活動挑題、設定前測／後測／前後都問；挑題時可以直接寫新題目。
- 前測、後測各有 QR 與連結，可開關。
- **即時填寫進度**：最上面切前測／後測，列出「還沒填」的人（應填＝正取報名者＋有簽到的），每 10 秒自動更新；報名卻沒來的另外列。
- 結果：每題前後平均、個人前後對照、開放式回答。其他區塊收起來。
- 下載 Excel：照園方 Google 表單回覆試算表的樣子（前測、後測各一張，量表寫成文字，下面接 COUNTIF 百分比表）。

### E. 場地借用

- 前台：月曆／手機版兩週清單（可翻頁）、預約、查詢與取消（用電話）。
  - 預約前**一定要勾同意規範**（跳出視窗；重要規範用紅色粗體）；伺服器也要擋。
  - 開放日期照「借哪一天」判斷（例：10/1 以後的時段才收），公告寫清楚。
  - 公開借用表的借用人姓名要遮。休館寫「全館休館」。
  - 場地可以設「借用提醒」（例：場地搬家），選到該場地、預約成功、查詢時都顯示。
- 後台：代登記、社工一次鎖多個時段（撞到就全部不鎖並列出）、閉館公告、使用統計、下載（含「預約時間」）、匯入舊網站資料（可重複匯入當同步）。
- 活動佔用的場地也算借用紀錄，跟月報同一個算法。

### F. 月報統計與社會局月報

- 月報統計可選月、季、全年度；統計基準可切「依出席月份（預設、政府用）」等。
- 三張分佈表：居住地區、年齡、身分別人次；可依活動分類篩選。
- **補登活動人次**：沒辦法進系統的課在這裡補（一場一列，一般生／原住民 × 男女），一起填地區與年齡分佈。
- **月報其他欄位**（自動儲存）：諮詢服務（固定七項）、1F交誼區、參訪單位、社區工作、會議與教育訓練、FB／IG。
- **社會局月報 Excel**：格式完全照園方檔案，從 1 月起一個月一張工作表（名稱用民國年月，例 11510），座標對齊到格，能用公式的地方用公式。系統上線前的月份用園方原本的檔案原封不動放進去。
- **0 人的課不上月報**（颱風停課、取消）：不列明細、不算場次、不算場地次數。

### G. 學生資料

- 一人一筆，搜尋、編輯、看報名紀錄、下載；可匯入 Google 表單回覆（同身分證視為同一人）。

## 第三部分：踩過的坑（不要再犯）

| 做過的事 | 結果 | 現在的做法 |
|---|---|---|
| 用 **TinyURL** 自動縮網址 | 縮出來的連結點不進去（`*.vercel.app` 常被縮網址服務當成可疑網址擋掉） | 網站自己做短網址（`/s/代號`）；有設 PicSee 才用 `pse.is`，失敗自動退回自己的 |
| **PicSee** API 預設給 `userXXXX.pse.is` | 網址還是太長 | 建立時指定網域 `pse.is`，不行再退回預設 |
| 做**人機驗證**（先自製算術題，再換 Cloudflare Turnstile） | 有些人一直過不了（網址沒加進 Cloudflare、LINE 內建瀏覽器、學校網路擋） | **整個停用**。要再開：所有網址加進 Cloudflare、模式選 Non-interactive、失敗要有備案 |
| **LINE 通知** | 使用者覺得沒用 | 不使用，程式留著 |
| 「每天場地不一樣」放在收合的上課日期面板裡 | 使用者找不到，以為不能設 | 放在「使用空間」正下方 |
| 額滿的活動放進「已截止／額滿」 | 使用者認為額滿還在開放報名（可排候補） | 額滿留在「開放報名中」，排在後面 |
| 停課（0 人）的課照樣進月報 | 月報多出沒上的課 | 沒人簽到的那一堂不上月報 |
| 統計頁和借用頁各算各的 | 數字對不起來 | 共用同一個算法 |
| 公開網頁有完整姓名或剩餘名額 | 隱私疑慮 | 姓名遮蔽、不顯示名額 |
| Vercel 預覽網址（`-git-…`）當成分享連結 | 別人點了要登入 Vercel | 分享連結、QR 一律用正式網址 |
| 使用者的電腦／手機是 Safari | 剪貼簿、下載圖片在 Safari 有限制 | 複製用 ClipboardItem（點下去當下就寫入）；QR 圖片直接畫在 canvas，不經過 SVG |

### 其他經驗

- 外部服務（Google 行事曆、縮網址、人機驗證）**都可能失敗**：失敗時存檔照常、畫面提醒，不能讓使用者卡住。
- 「事後補資料」這種需求很常見（監護人資料、月報手填欄位）：設計時就要想「沒填怎麼辦、誰提醒、在哪裡補」。
- 使用者會用 Excel 交給政府：Excel 格式要跟他原本的檔案一模一樣，他才能直接貼進大檔。
- 有日期區間的資料一律用**台灣時間**判斷。
