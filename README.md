# 少年培力園 活動報名系統

給少年培力園用的活動報名網站。少年在前台報名，工作人員在後台管理活動與名單。

**核心特色：報名過一次就不用再填第二次。** 之後報名任何活動，只要輸入
**姓名 + 身分證字號 + 出生年月日**，系統就會自動帶出上次填過的所有資料，
按一下就完成報名。

---

## 快速開始

需要 Node.js 20 以上，以及一個 Postgres 資料庫。

```bash
npm install
DATABASE_URL='postgres://使用者:密碼@主機:5432/資料庫' node server.js
```

第一次啟動會自動建好資料表，並放一個範例活動讓你試用。

然後打開瀏覽器：

| 頁面 | 網址 | 誰可以看 |
| --- | --- | --- |
| 活動總覽（報名首頁） | <http://localhost:3000/> | 所有人 |
| 查詢我的報名 | <http://localhost:3000/my> | 所有人 |
| 單一活動報名頁 | `/activity/<活動代稱>` | 所有人 |
| 工作人員後台 | <http://localhost:3000/admin> | 需要密碼 |

前台的導覽列只放三個：**活動總覽／場地借用／後台**。
「查詢我的報名」改放在活動總覽最上面一張看得懂的卡片裡
（報名過的人才會用到，擺在活動清單上面反而更找得到），
每一頁的頁尾也都有連結。

**後台密碼：`81599196`**（全形半形都可以輸入）

換 port：`PORT=8080 node server.js`

### 部署到 Vercel

1. 到 [vercel.com](https://vercel.com) 用 GitHub 帳號登入，選 **Add New → Project**，
   匯入這個 repo，其他設定都不用改，直接 Deploy。
2. 開一個資料庫：在 Vercel 專案的 **Storage** 分頁選 **Neon（Postgres）**，
   免費方案就夠用。建立後 Vercel 會自動把 `DATABASE_URL` 加進環境變數。
3. 到 **Settings → Environment Variables** 再加兩個（很重要，見下方「上線與安全」）：

   | 名稱 | 值 |
   | --- | --- |
   | `ADMIN_PASSWORD` | 你要用的後台密碼 |
   | `SESSION_SECRET` | 一串長亂碼，例如 `openssl rand -hex 32` 產生的 |

4. 回到 **Deployments** 按 **Redeploy**，讓新的環境變數生效。

網址會長得像 `https://你的專案名.vercel.app`，HTTPS 是自動的。

### 選用：新增活動自動進 Google 行事曆

設定好之後，每新增一個活動，它的每一堂課都會自動在指定的 Google 行事曆上
建立事件（改日期、改名稱會跟著更新，刪活動會一起刪）。標題長這樣：

```
[W] 停車場抽籤開始 1000-1100
```

事件顏色照活動的「負責工作人員」代號分：W 黃／J 藍／H 紅／V 綠／R 橙／
L 磚紅／ALL 灰／兩個人以上 紫。活動時間沒填就會是整天的事件。

要設定的話：

1. 到 [Google Cloud Console](https://console.cloud.google.com) 建一個專案，
   在 **API 和服務 → 程式庫** 啟用 **Google Calendar API**。
2. **IAM 與管理 → 服務帳戶 → 建立服務帳戶**，建好之後進去
   **金鑰 → 新增金鑰 → JSON**，會下載一個 JSON 檔。
   裡面的 `client_email` 與 `private_key` 等一下要用。
3. 打開那個 Google 行事曆的 **設定 → 與特定使用者共用 → 新增使用者**，
   把服務帳戶的信箱（`client_email`）加進去，權限選
   **變更活動**。沒做這一步，服務帳戶看不到那個日曆。
4. 在 Vercel 的 **Settings → Environment Variables** 加三個：

   | 名稱 | 值 |
   | --- | --- |
   | `GOOGLE_CALENDAR_ID` | 日曆 ID（設定頁最下面，長得像 `xxx@group.calendar.google.com`） |
   | `GOOGLE_SERVICE_ACCOUNT_EMAIL` | JSON 裡的 `client_email` |
   | `GOOGLE_PRIVATE_KEY` | JSON 裡的 `private_key`，整段貼上（含 `-----BEGIN PRIVATE KEY-----`） |

5. **Redeploy**。

三個變數只要少一個，這個功能就整個不啟用（不會報錯，只是不同步），
所以本機開發不用設。同步失敗（金鑰過期、Google 當機）也不會害你存不了活動 ——
活動照樣建得起來，只是存檔後的訊息會提醒「這個活動沒有進 Google 行事曆」，
修好之後把活動再存一次就會補上去。

**設好了但日曆上沒東西**：後台的 **使用說明 → 行事曆連線 → 測試連線**
會照順序試一遍（環境變數 → 服務帳戶登入 → 找得到日曆 → 建得了事件，
測試事件建完馬上刪掉），直接告訴你卡在哪一步。最常見的兩個是
第 3 步「忘了把日曆分享給服務帳戶」和第 4 步「分享成唯讀，權限要選變更活動」。

### 場地借用紀錄包含活動佔用的場地

後台 **場地借用** 頁的清單、使用統計、兩個下載按鈕，都把**活動佔用的場地**算進去
（新增活動時選了空間，每一堂課就佔住那間場地）。這是園方的認定：活動用了場地，
就是場地借用紀錄的一部分。

- 一堂課 × 一間場地一列，標「活動」；借用人寫「培力園活動」，負責人照活動的代號
- **人數是那一堂實際簽到的人數**（還沒上的課是 0），跟社會局月報同一個算法
- 活動那一列只能看、不能取消或刪除，按「到活動頁」去改時間與場地
- 使用統計多一欄「其中活動」，寫出每間有幾次、幾人次是活動 —— 數字跟
  社會局月報的「場地設施使用」完全一樣
- **社工先鎖了場地、同一時段又開活動，兩邊都算**。這是故意的（園方的算法），不是重複

### 社工鎖場地：一次鎖好幾個時段

後台 **場地借用 → ⚡ 社工鎖場地**。同一個場地、同一個名目，可以一次鎖好幾個時段
（例如社團整學期每週二 17:45–20:15、營隊連續五天 10:00–21:00）：

- 時段一列一個（日期＋開始＋結束），日期旁邊會寫星期幾，上面寫「共幾個時段」
- **＋ 隔天同一時間**／**＋ 下週同一時間**：照最後一列再加一列，時間一樣、日期往後排
- **每週重複到〔某天〕→ 產生**：以第一列為準，每週同一天同一時間排到那一天
- **全部先檢查才鎖**：只要有一個時段撞到別人（或跟自己這批重疊），
  就**一個都不鎖**，並把每一個撞到的時段跟撞到誰一次列出來 —— 不會鎖了一半
- API：`POST /api/admin/bookings` 帶 `slots: [{date, startTime, endTime}, …]`；
  不帶 `slots` 就是原本的單筆登記

### 場地借用的兩個下載按鈕

- **📥 下載這個月** —— 只匯出上面選到的那個月（有選場地就再篩場地）
- **📂 下載全部月份** —— 從頭到尾所有紀錄，不管上面選了什麼

兩個匯出的欄位一樣：日期、起訖、空間、來源、借用人、單位、電話、人數、
活動類型、用途、設備、負責人、狀態、備註。

### 補登活動人次

有些課程排課太雜、人員太雜，沒辦法一場一場開進系統（園方的例子是烘焙課，
一個月上好幾次、每次來的人都不一樣）。這種的在 **月報統計** 最上面的
**補登活動人次** 一次補完：上面填一次活動名稱／服務類型／項目，
下面一場一列填日期與人數（一般生男女、原住民男女），一次送出。

- 一列就是一場，日期限制在選定的月份裡（填錯月份是最難發現的錯）
- 填到最後一列會自動再長一列，每列有小計、下面有總計
- 有一列填錯就整批不寫入，不會只存進去一半
- 補進來的會加進月報總數，也會直接出現在社會局月報的活動明細

早期的補登只有月份與總人次、沒有日期與男女分格，那些資料還在，
在清單上會標「（未分）」；社會局月報上那幾列的人數欄會留白並在頁尾提醒，
按「編輯」補上日期與分格就會正常帶入。

#### 補登時一起填居住地區與年齡

補登的課沒有個別的報名資料，系統算不出這些人住哪、幾歲 —— 但月報的
三張分佈表要這些數字。所以補登表單裡（場次表下面）就有這兩塊，
**一個課程填一份**：

| 區塊 | 填什麼 |
|---|---|
| 居住地區人次 | 新北市 29 區全部列出來，在有人的區填人數 |
| 年齡人次 | 11歲以下／12～18／19歲以上全部列出來，在有人的年齡填人數 |

- 填的時機就是補登的當下 —— 社工手上正拿著簽到單，事後另外找一塊填，
  早就不記得那個月誰來過了
- **身分別不用填**：補登已經分過一般生男女與原住民男女，直接換算
- 選項全部攤開，一格一個區（或年齡），只填數字、沒人的空著 ——
  不用一列一列先選地區再填人數，Tab 一路跳下去就填完了；填了的格子會變綠。
  選項是固定的，不讓人自己打：手打「15歲」會跟簽到算出來的「15」
  對不起來，同一個年齡就變成兩列
- **可以留白**（趕時間先把人次補進去），但只要填了就得加起來等於這個
  課程補登的總人次。差幾個當場就寫出來（「上面是 10 人次，這裡目前是 7，
  還少 3 人次」），對上了才顯示「✓ 跟上面對得上」。前後端都會擋
- 同一次送出的那幾列共用一個 batch，這兩份掛在 batch 上；
  那批補登被刪光，數字也跟著清掉，不會留下對不到人的孤兒數字
- 同一個月有好幾個課程就各填各的，分佈表把它們加起來

### 月報其他欄位

社會局月報上還有幾塊系統本來沒資料的欄位，現在在 **月報統計 → 月報其他欄位**
直接填，填完就會帶進 Excel：

| 區塊 | 填什麼 |
|---|---|
| 參訪單位 | 日期、參訪單位、人次 |
| 社區工作（外部資源連結或合作） | 日期、連結單位、人次 |
| 各項會議及教育訓練 | 一位同工一列，個督／團外督／行政會議／教育訓練各幾次 |
| 少年培力園FB粉專 | 貼文數、瀏覽人次、內容互動總數 |
| 少年培力園IG | 貼文數、瀏覽次數、觸及人數、內容互動次數 |

- 五塊收在同一張卡裡，平常各佔一列，右邊直接寫出目前填了什麼
  （例如「2 筆　15 人次」「尚未填寫」），要改再點開
- 每一塊是一張直接打字的表，按該塊的「儲存」整塊存起來
- 整塊取代：刪掉一列之後直接按儲存就生效，不用一列一列刪
- 空白列會自動略過；日期限制在選定的月份裡
- 總計欄系統會幫忙加好
- 欄位定義在 `src/report-extras.js`，前台表單、後端驗證、Excel 三邊共用，
  要改欄位名稱或加欄位改那一個檔就好
- **各項會議及教育訓練會先帶入同工名單**，只要填次數。名單沿用「上一次填過的
  那個月」—— 有人離職或新進，在某個月把名字改掉、存起來，之後的月份就跟著
  新名單走，不用改程式。系統裡一筆都沒有時，用 `report-extras.js` 裡的預設
  （莊宛蒨、張穎欣、霍振偉、王庠茗、劉芷妤、楊志傑）。沒填的月份，社會局月報
  上照樣印出名字、次數留白。原表只給 5 列，同工超過 5 位時那一塊往下長一列。

剩下沒有做進系統的只有 **諮詢服務** 與右邊的 **總計表類**，那兩塊還是留白手填。

### 社會局月報（Excel）

後台 **月報統計 → 📗 社會局月報（Excel）**。要先選月份才按得下去。
下載到的是**那一年 1 月到選的月份，一個月一張工作表**（跟園方的大檔一樣），
工作表名稱用民國年月（2026-09 → `11509`），打開時停在最後一張（選的月份）。
年初還沒有任何資料的月份（系統開始用之前）不產生 —— 一張全是 0 的表看起來像
「那個月沒服務」；選的那個月一定有。

**格式完全照園方的檔案**：字型（標楷體／Times New Roman）、粗細框線、底色、
數字與日期格式、欄寬、列高、檢視比例、列印設定（A3 橫印 39%），
都是從園方那份「新北市少年培力園每月服務統計 2026」的 `11509` 整張抽出來的，
存在 `src/bureau-template.js`（只有格式，沒有任何儲存格的值）。
園方之後改了表格格式，拿新的檔案重抽一次就好：

```sh
node scripts/extract-bureau-template.mjs 月報.xlsx 11510
```

位置也**對齊到格**：諮詢服務在 3–12 列、場地在 15–25、參訪在 28–33、
社區工作在 35–43、會議在 46–53、活動明細在 M–V 的 3–55。
會長的只有兩塊：活動明細（原表 50 列）與會議的同工（原表 5 位），
超過就往下長，長出來的列用原表中間那一列的格式，總計列跟著往下搬
（跟在 Excel 插入列一樣）。

系統會自動填好的：

- **場地設施使用** —— 外面登記的借用 ＋ 培力園自己活動佔用的場次，
  兩者相加。一堂課用到兩個空間，兩邊各算一次。
- **活動明細** —— 一堂課一列，人數依「性別 × 身分別」拆成一般生男／女、
  原住民男／女。**以當天實際簽到為準**，沒來的不算；新住民歸在一般生
  （社會局那份表只有一般生與原住民兩欄）。
- **全項統計** —— 活動明細依服務類型（團體工作／方案服務／社區工作）
  分組的場次與人次。
- **團體服務** —— 服務類型是「團體工作」的那些，男女 × 身分別 ＋ 次數。
- 參訪單位、社區工作、會議與教育訓練、FB／IG 由「月報其他欄位」帶入（見上一節）。

**諮詢服務**系統裡沒有資料，留白給社工手填 —— 但「每月諮詢紀錄」總計表與
「當月服務總人次」都寫成公式指過去，他填完那七列其他格子會自己算出來。
其餘六張總計表（親職教育、親子活動、育樂、社區服務、在職訓練、其他福利）
對不到可靠的來源，只做框架留白，不會自己編數字。
場地那三欄男／女／其他也留白 —— 借場地時沒有問性別。

報表上的九個空間裡，**1F交誼區、2F會談室、2F縫紉教室、2F卡啦OK區**
沒有開放線上登記，所以那四列是空的（交誼區原表本來就只算人次、不算次數）。
對照表寫在 `src/bureau-report.js` 的 `VENUE_ROWS`，空間名稱改了就改那裡。
原表**沒有 3F烘焙教室那一列**，那個月真的有借到的話，表的下面會多一行提醒，
不會無聲無息地少掉。除了這種要人工處理的提醒，表的下面不印任何說明文字（園方的檔案沒有）。

Excel 是自己產的（`src/xlsx-write.js`），沒有裝任何套件 ——
xlsx 就是一個 zip 裝 XML，Node 內建的 zlib 就壓得出來。

### 標誌

原圖是 `public/assets/logo.png`（培力園的橫式標誌，去背）。網站實際用的是
從它產出來的小檔，換標誌的話把新圖蓋掉 `logo.png`，再跑一次：

```
node scripts/make-logo-assets.mjs
```

會產出：`logo-banner.webp／.png`（前後台頁首的整條標誌）、`favicon.png`
（瀏覽器分頁圖示，只取那台飛機）。
頁首是白底 —— 標誌是紫色字、白邊，放在深綠底上會糊掉；綠色退成底下一條細邊。

### 把舊的借用紀錄搬進來

後台 **場地借用 → 📤 匯入舊資料**，直接上傳原本那張「預約資料」試算表
（.xlsx，不用先轉 CSV）。欄位照舊表的順序認：時間戳記／預約人／電話／
單位／人數／活動類型／空間／日期／開始／結束／設備／狀態。

- 先按「**先試算看看**」：會回報會新增幾筆、更新幾筆、沒變幾筆、有幾列讀不懂
- 空間名稱的錯字（三樓烘烘焙教室、三樓烘炙教室）會自動對到正確的空間
- 電話 `0000000000` 或預約人「培力園社工」→ 歸到「社工鎖場地」；
  狀態「閉館」或活動類型「閉館公告」→ 歸到「閉館公告」
- **同一筆不會匯兩次**，比對的是舊表第一欄的**時間戳記** ——
  舊系統每一筆送出都有自己的時間戳記（一份 637 列的檔案就有 637 個
  不重複的值），拿它當唯一編號最準
- **可以重新匯出一份新的再匯一次**，等於跟舊系統同步一次：
  - 狀態改過的（例如後來被取消）→ **更新**那一筆，不會變成兩筆
  - 人數、時間改過的 → 一併更新
  - 新增的 → 新增
  - 完全沒變的 → 什麼都不做
  - 結果畫面會分開講「新增 N 筆、更新 N 筆、沒變略過 N 筆」
- 取消之後又用同一個時段重借，是**兩次不同的送出**、時間戳記不一樣，
  所以會留成兩筆（一筆已取消、一筆有效），跟舊系統一致
- 之前匯過、但這次的檔案裡**對不到**的，會整批列出來，旁邊有一顆
  「🧹 清掉這 N 筆」。系統不會自己刪，但按一下就清得掉：
  - 最常見的來源是**用舊版程式匯了兩次不同時間匯出的檔案**：某一筆在
    兩次匯出之間被取消了，舊版把它當成新的一筆又存一份，於是同一個借用
    同時有「有效」跟「已取消」兩列 —— 有效那列就一直被算進統計，
    數字會比舊網站多。清掉那幾筆就一致了
  - 另一種是那一列在舊系統裡被整列刪掉了
  - 清除只會動「從舊的借用表匯入」的紀錄，**系統裡自己登記的借用
    絕對不會被刪**（就算 id 傳進去也一樣，後端會擋）
- 這個功能之前匯進來、還沒有時間戳記的舊資料，第一次用新版匯入時會照
  「空間＋日期＋時間＋借用人」認回來並補上時間戳記，不會變成兩倍
- 匯入是照抄，不套借用規則 —— 舊資料本來就有超過 3 小時、
  跨過開館時間的紀錄，那是歷史事實

### 場地借用規範：預約前一定要按同意

- 前台一點「我要預約」就跳出規範視窗，勾「我已閱讀並同意遵守場地借用規範」
  才按得下「我同意，開始預約」、看得到預約表單；按「先不要」就留在場地借用表。
  同一次打開頁面同意過一次，之後切回來、送出都不再跳（送出時如果還沒同意，會再跳一次）
- 伺服器也會擋：沒帶同意的前台借用一律不收（避免有人繞過網頁直接送）；社工從後台代登記不用
- 飲食規範放大、紅字粗體。規範文字在 `src/booking-rules.js` 的 `RULES_TEXT`，
  哪一條要紅字就在後面加 `'important'`

### 場地借用的開放日期（10/1 以後的時段現在就能預約）

線上借用照「**借哪一天**」判斷，不是照「哪一天送出」：**現在就能預約 2026-10-01 以後的時段**，
9/30（含）以前的場地維持在原網站借用。開放日寫在 `src/booking-rules.js` 的
`OPENS_ON`，每次有人打開頁面、送出借用時都重新判斷一次。

10/1 以前：

- `/booking` 最上面掛著「📅 10/1 起的預約，已經可以在這邊預約了！／9/30（含）以前的場地，請維持在原網站借用」，月曆直接從 10 月開始，日期最早只能選 10/1
- **伺服器真的會擋**：前台送出 9/30 以前的借用會被拒絕，並回同一段說明
- 社工從後台代登記、鎖場地不受影響，哪一天都能登記；後台那一頁會提醒前台只收 10/1 以後
- 10/1 00:00 起公告自動消失，不用做任何事

環境變數 `BOOKING_UNDER_CONSTRUCTION` 可以蓋過日期：

| 設定 | 效果 |
|---|---|
| 沒設（建議） | 照日期：只收 10/1 以後的時段 |
| `0` | 不看開放日，哪一天都能借（提早全開） |
| `1` | 整個關起來（臨時要暫停線上借用時用；就算過了 10/1 也關著） |

### 場地借用的 LINE 通知：不使用

園方決定不用 LINE 通知（新借用推播、每日匯報），所以 Vercel 不用設
`LINE_CHANNEL_ACCESS_TOKEN`／`LINE_TARGET_ID`／`CRON_SECRET`，
`vercel.json` 也沒有排每日匯報的排程。借用一律在後台「場地借用」看。

程式還留著（`src/line.js`），沒設環境變數就整個不動作；
哪天想用，把上面三個變數設好、在 `vercel.json` 加回
`"crons": [{ "path": "/api/cron/daily-booking-report", "schedule": "30 8 * * *" }]` 就會恢復。

--- | --- |
| `LINE_CHANNEL_ACCESS_TOKEN` | LINE Developers → Messaging API → Channel access token |
| `LINE_TARGET_ID` | 要收通知的人或群組 ID |
| `CRON_SECRET` | 隨便一組長字串，排程呼叫匯報端點時要帶 |

這支機器人是「只推播、不接收」，所以 **不需要設 webhook**，LINE 那邊
不用改任何設定，換伺服器也不影響已經加好友的人。

每日匯報走 `POST /api/cron/daily-booking-report`，`vercel.json` 裡已經
排好每天 08:30 UTC（台灣 16:30）。Vercel 會自動帶 `CRON_SECRET`；
用 GitHub Actions 之類的排程也可以，自己帶 `Authorization: Bearer <CRON_SECRET>`。

## 前台：少年怎麼報名

進到活動頁之後有兩條路：

**1. 報名過培力園活動的老朋友**
輸入姓名、身分證字號、出生年月日 → 系統帶出完整資料 → 只要回答這次活動的
三個問題（從哪裡得知、報名原因、全程參與承諾）就送出。資料有變動（換學校、
升年級、換手機）可以按「資料有變動，我要修改」當場改，改完會同步更新後台主檔。

**2. 第一次報名**
填完整報名表（少年基本資料 + 監護人保險資料 + 活動問題）。送出後資料就存進
後台，下次報名就走第 1 條路。

系統會自動擋掉：重複報名同一個活動、額滿、過了報名截止日、活動已結束。

## 後台：工作人員怎麼用

### 活動管理（`/admin`）

- **新增活動**：填活動名稱與日期就能建立，其他欄位可留白。
  建立後會給一個報名網址，用「複製連結」按鈕就能貼到 LINE 分享。
- **每個活動一個子頁面**：點活動名稱進入該活動的報名名單。
- **過期自動歸檔**：活動日期一過，隔天就自動從「即將舉行」移到「過往活動」，
  不用手動搬。前台也會同步移到過往活動頁。
- **暫停報名**：編輯活動時取消勾選「開放報名」，活動還看得到但無法送出。
- **活動分類**（只有工作人員看得到，前台不顯示）：
  - 方案分類：社區與親子培力方案／微創實驗方案
  - 服務類型：團體工作／方案服務／社區工作
  - 細分類：自由填寫（例如「親子共學」），月報可以用它篩選，
    同一類的活動請填一樣的名稱才統計得在一起。
- **刪除活動**：需要輸入「刪除」兩個字確認。會連同該活動的報名紀錄一起刪除，
  但**學生的基本資料會保留**在學生資料總集裡。

### 單一活動名單（`/admin/activity/<id>`）

- 看這個活動的完整報名名單，可以用姓名、身分證、學校、電話、監護人搜尋。
- 點姓名展開這個人的完整報名內容，可以加工作人員備註（例：素食、需要接送）。
- **刪除某人的報名**：需要輸入該少年的姓名確認，避免手滑。
  刪掉的只是這一筆報名，他的基本資料還在。
- **下載這個活動的報名資料（CSV）**：欄位順序跟 Google 表單匯出一致，
  用 Excel 打開中文不會變亂碼。
- 「列印名單」可以直接印出當天要帶的紙本名冊。

### 連續性課程與簽到

活動可以是**單日**（例如淨灘），也可以是**連續性課程**（例如水電課 7-8 月每週三）。
兩者用同一套結構：一個活動底下有 1 到 N 個「場次」。

**建立多天活動**：新增活動時展開「這個活動不只一天？」，填最後一天，
再選上課方式：

- **連續每一天** —— 三天兩夜營隊、連續兩天的工作坊。
  例：12/1 到 12/3 ＝ 3 場。
- **每週固定星期** —— 勾選星期（可複選）。
  例：7/1 到 8/31 的每週三 ＝ 9 堂。

活動的起訖日期會自動跟著第一場與最後一場走。

> 連續性課程的「已結束」是看**最後一堂**，所以 7 月開課、8 月才結束的課程，
> 課還在上的期間不會被歸到過往活動。

**簽到**：少年掃 QR → 選課程 → 填姓名與身分證字號 → 完成。

- 簽到頁在 `/checkin`，只列出**今天**有課的場次。
- QR 可以帶場次代號（`/checkin?session=xxx`），掃進去就預選好那一堂，
  少年只要填名字。到後台的活動頁 →「簽到與出席」→ 任一場次的「QR」
  就能顯示並列印。
- 簽到只要姓名 + 身分證字號兩項（比報名少一項生日），現場隊伍才不會卡住。
- **沒報名的人也能簽到** —— 現場常有臨時來的少年，這些人算進出席人次，
  但會標記成「未報名」讓工作人員知道。
- 同一個人同一場只能簽到一次，由資料庫把關。
- 沒帶手機的少年，工作人員可以在後台代簽。

**出席總覽**：後台活動頁的「簽到與出席」分頁，會顯示報名者 × 各場次的
勾勾表，一眼看出誰全勤、誰缺席，以及每場的簽到人數。

### 月報統計（`/admin/reports`）

每個月要交給政府的數字。三張分佈表：**居住地區人次、年齡人次、身分別人次**，
另外附上活動場次、服務人次與實際人數（去重）。

三張表同時算兩種來源：線上報名簽到（系統自己算的）與補登人次（社工填的）。
有補登的月份會拆成「簽到／補登」兩欄再加總，沒有的月份就維持原本三欄。
補登那一半要在補登時一起填居住地區與年齡才有數字（見上面那一節），
身分別則是從補登的一般生／原住民分格直接換算。

- **可以回看任何一個月**，月份下拉選單會列出所有有資料的月份。
  預設顯示這個月（台灣時間）；月初這個月還沒資料時，會自動退回最近有資料的月份。
- **統計基準可以切換**：
  - **依出席月份（預設）** ＝ 每一次簽到算一人次。連續性課程來了 6 堂就算
    6 人次，這是實際的服務量，也是政府要的數字。
  - 依活動舉辦月份 ＝ 本月辦了哪些活動、有多少人報名。
  - 依報名月份 ＝ 本月有多少人送出報名。
  三種算出來的數字不一樣，看政府要哪一種。
- 用出席基準時，年齡是按**上課那天**算的（連續性課程橫跨生日也準），
  而且現場臨時參加、沒有報名紀錄的人也算得進去。
- **可以依活動分類篩選**（方案分類／服務類型／細分類），
  三張分佈表會跟著只算該分類的活動。
- 有活動還沒分類時會跳出提醒，避免月報少算。
- 可以下載 CSV 或直接列印。

### 學生資料總集（`/admin/students`）

所有報名過的少年都在這裡，一個人一筆，不會因為報名多次而重複。

- **搜尋**：姓名、身分證字號、學校、居住區域、手機、住家電話、LINE ID、
  Email、監護人姓名與電話、生日（西元或民國）都搜得到。
- 點姓名看完整資料 + **他報名過哪些活動**。
- 可以直接編輯資料（例如升學換學校），改完之後的活動都會用新資料。
- 刪除學生會連同他所有報名紀錄一起刪除，需要輸入姓名確認。
- 可以下載全部學生資料，或只下載目前搜尋結果。

# 建立新活動並匯入

- 新建立的活動預設是**關閉報名**的（避免舊活動被誤開放），
  要開放的話到後台編輯活動勾選「開放報名」。

## 資料存在哪裡

全部存在 Postgres 資料庫裡，共四張表：`activities`、`students`、
`registrations`、`login_attempts`。資料表會在第一次啟動時自動建立。

- 一個人只會有一筆 `students` 紀錄，用**身分證字號**當唯一鍵，
  所以同一個少年報名十次活動也不會重複建檔。
- 「同一個人不能重複報名同一個活動」是由資料庫的唯一索引把關的，
  就算兩個請求同時進來也擋得住。
- 報名時整段流程會鎖住該活動，**兩個少年同時按送出也不會超收名額**。
  （這在 Vercel 上特別重要，因為會有多個執行實例同時處理請求。）

**備份**：Neon 免費方案有時間點還原（PITR）。要自己留一份的話，
到後台的「學生資料總集」按下載 CSV，或用 `pg_dump` 匯出整個資料庫。

## 上線與安全

這套系統存的是未成年人的身分證字號、地址、監護人資料，屬於高敏感個資。
正式對外開放前請務必做到：

1. **一定要設 `ADMIN_PASSWORD`。** 預設的 `81599196` 是寫在
   `src/config.js` 裡的，而這個 repo 是公開的 —— 任何人看得到原始碼
   就等於知道後台密碼。密碼建議用長一點的英數混合，純數字 8 碼很容易被猜到。
2. **一定要設 `SESSION_SECRET`。** 沒設的話，登入權杖的簽章金鑰會從密碼推導，
   猜到密碼的人可以自己偽造登入權杖。用 `openssl rand -hex 32` 產一串貼上去即可。
3. **HTTPS**：Vercel 自動提供，自架的話要自己處理（Caddy、Nginx + Let's Encrypt、
   Cloudflare Tunnel 都可以）。沒有 HTTPS 的話報名內容和密碼都是明文傳輸。
4. 後台是**單一共用密碼**，沒有分帳號，所以看不出是哪位工作人員做的操作。
   如果需要追蹤誰刪了資料，要再擴充成多人帳號。

已經內建的防護：

- 後台所有 API 都要驗證登入權杖，密碼比對用定時安全比較。
- 後台密碼連續輸錯 10 次會鎖 15 分鐘（同一個 IP）。次數記在資料庫，
  所以 serverless 換執行實例也擋得住。
- 老朋友查詢要姓名、身分證、生日**三項全對**才會回傳資料，
  對一兩項不會透露任何訊息；同一個 IP 10 分鐘內最多查 30 次。
- CSP 只允許同源資源，沒有用任何外部 CDN。
- CSV 匯出會處理 Excel 公式注入（開頭是 `=` `+` `-` `@` 的欄位）。
